Task 3: Docker Fundamentals
1. Objective
The objective of this task was to understand Docker fundamentals, install and verify Docker, work with Docker images and containers, and run a web server inside a container.
2. Environment and Tools
Operating System: Windows with WSL 2 (Ubuntu)
Editor: Visual Studio Code
Container Platform: Docker Desktop
Docker Engine: 29.9.2
Docker Compose: v5.6.1
3. Docker Installation and Verification
Installed Docker Desktop and verified that Docker was available through WSL 2.
Commands used:
docker --version
docker compose version
docker info
The commands confirmed that both the Docker client and server were working.
4. Running the Hello World Container
Executed the official Docker test image:
docker run hello-world
Docker downloaded the image, created a container, and displayed the successful installation message.
5. Inspecting Images and Containers
Used the following commands:
docker images
docker ps
docker ps -a
These commands helped me understand the difference between Docker images and containers and identify running and stopped containers.
6. Working with Ubuntu Containers
Started an interactive Ubuntu container:
docker run -it ubuntu bash
Practised Linux commands inside the container:
whoami
pwd
ls
cat /etc/os-release
Created a directory and files:
mkdir docker-practice
cd docker-practice
touch hello.txt
echo "Hello from my first Docker container!" > hello.txt
cat hello.txt
Also practised appending text, copying files, listing files and removing files.
7. Working with Alpine Containers
Started an interactive Alpine container:
docker run -it alpine sh
Verified the operating system:
whoami
pwd
ls
cat /etc/os-release
Created and inspected a practice file:
mkdir practice
cd practice
touch docker.txt
echo "I am learning Docker containers." > docker.txt
cat docker.txt
ls -l
This demonstrated that Docker supports lightweight Linux images such as Alpine.
8. Container Lifecycle Management
Practised starting and stopping an existing container:
docker start charming_moser
docker ps
docker stop charming_moser
docker ps -a
This helped me understand how containers can be restarted and stopped without creating a new container each time.
9. Running an Nginx Web Server
Downloaded and started an Nginx container:
docker run -d --name nginx-practice -p 8085:80 nginx:alpine
Verified the running container and viewed its logs:
docker ps
docker logs nginx-practice
Checked the Nginx version:
docker exec nginx-practice nginx -v
Inspected its configuration:
docker inspect nginx-practice
The inspection confirmed that host port 8085 was mapped to container port 80.
10. Browser Verification
Opened the following address in the browser:
http://localhost:8085
The Nginx welcome page appeared successfully, confirming that the web server was running inside the Docker container and accessible from the host machine.
11. Key Concepts Learned
Docker Image: A packaged template used to create containers.
Docker Container: A running or stopped instance of an image.
Docker Hub: A registry where Docker images can be downloaded.
Port Mapping: Connects a port on the host machine to a port inside a container.
Detached Mode: Runs a container in the background using -d.
Interactive Mode: Allows a user to access a container’s shell.
Docker Logs: Displays output generated by a container.
Docker Inspect: Shows detailed information about a Docker object.
Container Lifecycle: Includes creating, running, stopping and restarting containers.
12. Challenges Faced
Initially, the Docker command was unavailable in my Ubuntu WSL terminal because Docker Desktop’s WSL integration had not yet been activated. I installed and configured Docker Desktop, enabled the required integration, and verified that the Docker client and server were working correctly.
I also learned to distinguish between running containers and stopped containers when inspecting Docker output.
13. Outcome
Successfully installed and verified Docker, worked with Ubuntu and Alpine containers, practised basic container lifecycle commands, and deployed an Nginx web server using Docker. The Nginx welcome page was successfully accessed through the browser using port 8085.
